# Lumen Diff

Настольное приложение на Rust для сравнения фотографий и RAW. Интерфейс — **GPUI + GPUI Kit**, вычисления — **wgpu / DirectX 12** на Windows (Metal на macOS, Vulkan на Linux). Тёмная палитра и компактные контролы ориентированы на Redlamp.

## Сборка и запуск

Требуются актуальный stable Rust, Python 3.12+ и C++17-компилятор. На Windows установите **Visual Studio Build Tools → Desktop development with C++** и Windows SDK. Для GPU-обработки нужен DX12-драйвер; OpenCL SDK и CMake не нужны.

```powershell
python scripts/prepare.py
cargo run --release
cargo run --release -- "D:\Photos\A.NEF" "D:\Photos\B.NEF"
cargo run --release -- "D:\Photos\session"
cargo run --release -- --recursive "D:\Photos"
```

Если Cargo не находится в PATH: `& "$env:USERPROFILE\.cargo\bin\cargo.exe" run --release`.

`scripts/prepare.py` загружает **тот же форк и commit LibRaw, что зафиксирован в `../redlamp/config/vendored-libs.json`**, и проверяет SHA-256. Соседний Redlamp не изменяется и не нужен для последующих сборок. Обычная upstream LibRaw не подменяет этот форк: в нём находится декодер Nikon HE/HE*. Pin: `f4956c404fba0c6035ce9e06353d4b4ffe068fc7`. Сборка читает авторитетный список C++-файлов из `Makefile.dist` форка.

На Linux также нужны системные зависимости GPUI/Wayland/X11 и диалогов RFD. В этой рабочей среде проверяется Windows; остальные платформы требуют отдельных сборок и замеров.

## Использование

- Кнопки **Добавить изображение**, **Добавить папку** и **Очистить список** закреплены над списком. **Включая подпапки** включает рекурсивное добавление папок, также для drag-and-drop. В CLI есть `--recursive`.
- Выбирайте изображения простыми щелчками: первый файл становится A, второй — B. Следующий новый файл заменяет B; повторный щелчок снимает выбор. Если снять A, оставшийся файл становится A. Отдельных слотов и кнопок назначения нет.
- **Очистить список** отменяет незавершённое добавление/декодирование, освобождает выбранные кадры и миниатюры. Исходные файлы и дисковый кэш не удаляются. Поздние результаты отменённых заданий не заполняют список снова.
- Меняйте порядок перетаскиванием строк или кнопками **↑ / ↓** внизу списка. A/B привязаны к идентификаторам, а не позициям строк.
- **Single** показывает A или B; **Diff** — абсолютную RGB-разность с усилением **1/4/16/64/256×**; **Both slider** — разделитель; **Both click** — A, пока не удерживается левая кнопка мыши или пробел. Кнопки `1…4` переключают режимы.
- Колесо масштабирует у курсора. Перетаскивание изображения панорамирует; средняя кнопка панорамирует в любом режиме. В режиме Slider тяните ручку разделителя. Есть **Fit to screen / 100% / 200% / 400%**, `F` или `0` — Fit.
- Зум и нормализованная позиция центра сохраняются при смене кадров и перестановке A/B. 100% — один исходный пиксель на один физический пиксель экрана; учитывается DPI.
- Изображение B приводится к геометрии A с билинейной интерполяцией. При разном разрешении показывается предупреждение; это не автоматическое совмещение сцены и не поиск смещения.
- **Вычитание Gaussian** вычисляет `I − Gσ(I)` отдельно для обоих кадров, затем сравнивает остатки. σ от 0.3 до 20 пикселей A; ядро обрезается на ±3σ, края продолжаются ближайшим пикселем. Для B σ масштабируется по обеим осям. В Single/Slider/Click ноль остатка показан средним серым; Diff остаётся абсолютным, с нулём в чёрном.
- `Ctrl+O` добавляет файлы; `Ctrl+Shift+O` — папку. `F1` или кнопка **Справка** открывает отдельное окно с управлением. `←/→` меняют последний выбранный кадр; `Home/End` переходят к началу/концу списка.

## Производительность и ограничения

- GPUI `uniform_list` создаёт только видимые строки. Сканер выдаёт пути порциями по 256; при открытии каталога не декодирует полные кадры и не создаёт 10 000 заданий на декодирование.
- Два фоновых работника постепенно строят миниатюры. Видимые строки имеют приоритет; ограниченная очередь держит не более четырёх ожидающих заданий. Для RAW выбирается наименьший подходящий встроенный JPEG, без полного проявления при отсутствии preview.
- LRU миниатюр в RAM: до 1024 изображений размером не более 160×112 (около 70 MiB пикселей). Дисковый кэш с ключом путь/размер/mtime ограничивается 512 MiB с периодической очисткой. Для каталога из 10 000 файлов не выделяются 10 000 GPU-текстур.
- `--cache-dir` задаёт родительский каталог кэша. Запись/очистка происходит только в собственном подкаталоге `lumen-diff-v1` с маркером владельца и только для cache-файлов с хешированными именами. Непустой каталог без маркера не очищается; исходные фотографии приложение не изменяет.
- RAW-декодирование и проявление выполняются LibRaw в двух фоновых потоках; 16-битный sRGB, as-shot WB, без auto-brightness, шумоподавления и резкости, быстрый bilinear demosaic. Это **не** цветовой pipeline Redlamp. Первый decode RAW не обещает укладываться в 100 мс. Некоторые камеры, в том числе Nikon Z5 II/Z50 II, могут не иметь полноценной цветовой матрицы в pin форка.
- RAW читаются через read-only memory map: для миниатюры не копируется в RAM весь сжатый файл. Не изменяйте и не обрезайте исходники во время чтения. Небольшой LRU декодированных кадров ограничен примерно 1 GiB (минимум два кадра); соседние кадры последнего выбранного файла подготавливаются после выбранных.
- Два активных RGB16-кадра остаются в GPU-памяти. Gaussian выполняется двумя separable compute-проходами с float32-остатком и общим scratch-буфером; результат кэшируется до смены кадра/σ, а память переиспользуется при смене σ. На каждое движение передаются параметры камеры и считывается только BGRA8 viewport, а не 45 Мп; порядок каналов для GPUI формируется прямо в shader. При паре 45 Мп high-pass требует порядка **2 GiB VRAM** помимо UI и драйвера; обычное сравнение — примерно 0.5 GiB.
- Между отдельным compute-device и GPUI пока есть readback/upload экранного результата. **Zero-copy с GPUI не реализован**: выбранный GPUI на Windows рисует через DX11. Почему выбран DX12 вместо OpenCL: [compute-decision.md](compute-decision.md).
- Render worker хранит только последнее ожидающее задание; устаревшие результаты не заменяют актуальное изображение. Тяжёлая работа не выполняется в UI-потоке. В Single, Both slider и Both click подготовлены **две полные экранные текстуры** A/B. Разделитель только меняет GPU clipping в GPUI; он не запускает decode, Gaussian, compute, readback и не создаёт новые image handles. Смена A/B в Single и нажатие в Both click также используют готовые текстуры. При зуме/панорамировании, смене кадров или параметров фильтра текстуры подготавливаются заново.
- При недоступном GPU или ошибке compute включается фоновый CPU/Rayon fallback с сообщением. `--cpu` включает его явно. Это режим совместимости, **не** гарантия задержки до 100 мс.
- Разность вычисляется в 16-битном RGB-кодовом пространстве, не в исходной Bayer-мозаике. Различия проявления, экспозиции, WB, геометрии и встроенных профилей также попадают в Diff. ICC-приведение к единому рабочему пространству для растров и HDR tone mapping пока не реализованы. EXR приводится к RGB16, значения вне диапазона 0…1 обрезаются.
- Повреждённый RAW обрабатывается в процессе приложения, без отдельного sandbox-процесса. Не открывайте недоверенные RAW в этой версии.

## Проверки и измерения

```powershell
cargo fmt --check
cargo test
cargo test gpu_matches_cpu -- --ignored --nocapture
cargo run --release -- --benchmark --iterations 30
cargo run --release -- --benchmark "D:\Photos\A.NEF" "D:\Photos\B.NEF"
cargo run --release -- --benchmark --cpu
cargo run --release -- --probe "D:\Photos\HE.NEF" "D:\Photos\HEstar.NEF"
```

Без файлов benchmark создаёт пару 8256×5504 (~45.4 Мп), прогревает GPU, измеряет cold upload, первый Gaussian и median/p95 для pan/zoom/gain с и без high-pass. Вывод — JSON. Это время compute + readback + копия viewport в host Vec, **не** end-to-end задержка от мыши до экрана. Проверка 100 мс должна учитывать конкретную видеокарту, размер viewport, холодный/прогретый кэш, σ и загрузку системы; сам выбор DX12 этого не гарантирует.

Воспроизводимые локальные проверки и фактические результаты: [validation.md](validation.md). `python scripts/fixtures.py library` создаёт нагрузочный каталог из 10 000 PNG; `python scripts/fixtures.py raw` загружает два CC0 Nikon Z9 HE/HE* с проверкой SHA-256. На Windows `python scripts/ui_smoke.py --tail` проверяет нативное окно и сохраняет снимки (нужен Pillow).
