# Выбор вычислительного backend

Дата: 31 октября 2026.

## Решение

Вычисления выполняются через Rust `wgpu`: DirectX 12 на Windows, Metal на macOS, Vulkan на Linux. OpenCL не является зависимостью приложения. UI остаётся на GPUI, через совместимый pin GPUI Kit 0.8.1.

Пользователь первоначально выбрал OpenCL, затем предложил рассмотреть DX12 и делегировал решение. Обе технологии подходят для parallel per-pixel diff, ресэмплинга и separable Gaussian. Ни одна не гарантирует сама по себе задержку до 100 мс.

## Сравнение

| Критерий | OpenCL | DX12 через wgpu |
| --- | --- | --- |
| Поставка на Windows | Требуется работающий OpenCL ICD/runtime от производителя | Используется DX12-драйвер системы; отдельно ставить OpenCL не требуется |
| Поддержка Rust | Возможна, но низкоуровневое управление и FFI требуют осторожности | Типизированное управление ресурсами и валидация wgpu |
| Вычислительные возможности | Более широкий compute-oriented API, включая возможности вне WebGPU | Достаточно storage buffers, float32 compute и workgroups для наших фильтров |
| Переносимость | Зависит от доступных OpenCL-драйверов; OpenCL deprecated у Apple | WGSL-ядра используются через DX12, Vulkan и Metal |
| Скорость конкретных ядер | Определяется драйвером, памятью и алгоритмом | Также требует измерений; заведомое превосходство над OpenCL не заявляется |
| Обмен с GPUI | Не бесплатный; нужен explicit interop | Тоже не бесплатный: выбранный Windows GPUI использует D3D11, не D3D12 |

Прямой DX12/HLSL без wgpu не выбран: ручное управление descriptors, barriers и lifetime увеличивает объём платформенного кода без доказанной выгоды для этих алгоритмов. `gogpu/ui` — Go-фреймворк, его код не добавляется в Rust-приложение. Его README показывает DX12 как один из графических backend, а не как рекомендацию, основанную на benchmark обработки RAW.

## Копирование и память

Исходники хранятся в packed RGB16 storage buffers. При загрузке нет отдельного переупаковывания каждого пикселя в RGBA32F. Промежуточные Gaussian-данные — RGB32F; знак остатка не теряется, 16-битный шум не квантуется в half-float. Scratch используется повторно. Полноразмерный diff-буфер не создаётся: разность, усиление, геометрия и режим объединены в viewport shader.

Считывается только viewport BGRA8, уже в порядке каналов GPUI. Его данные передаются в обычное GPUI изображение; zero-copy или общего устройства с GPUI пока нет. Для устранения этой последней передачи нужен отдельный проект интеграции с нативным renderer GPUI, с проверкой синхронизации и времени жизни текстур. Он не должен подменяться обещанием «DX12 значит никаких копий».

## Проверка

CPU-референс и native-GPU regression сравнивают пиксели всех режимов, разные разрешения, включённый/выключенный Gaussian и packed RGB16 с нечётным числом samples. Допуск отображения — 1 уровень RGBA8. `--benchmark` отдельно измеряет cold load и интерактивный warmed path на 45 Мп. Производительность и корректность не выводятся из README стороннего GUI.
